# 05. リスクと対策 / OS別の注意点

## 1. リスク

### R1. 長時間録音でのデータ損失【最重要】
- **リスク**: アプリのクラッシュ、OSのスリープ、デバイス切断で3時間の会議が失われる
- **対策**:
  - メモリ保持をしない。5秒ごとに flush + `sync_data()` + WAVヘッダ更新
  - 起動時のクラッシュ復旧（ヘッダ修復）
  - 録音中はスリープ抑止（macOS: `IOPMAssertion` / Windows: `SetThreadExecutionState`）
  - デバイス切断を検知したら録音を安全に確定し、UI に明示（無音のまま録り続けない）
  - 録音中は 1 分ごとに空き容量を確認し、閾値を下回ったら警告

### R2. whisper.cpp のビルド依存
- **リスク**: CMake / C++ ツールチェーンが無いとビルドできない。CMake 4 系は古い `cmake_minimum_required` を拒否する
- **対策**: 開発環境要件を README に明記。配布時は CI でビルド済みバイナリを生成し、利用者にはビルド環境を要求しない

### R3. 文字起こしの処理時間
- **リスク**: 3時間の音声を large モデルで処理すると長時間かかる
- **目安**: Apple Silicon (Metal) の `medium` でおおむね実時間の 1/5〜1/10。3時間 → 20〜40分
- **対策**:
  - 進捗を必ず表示し、キャンセル可能にする
  - 既定モデルは `large-v3-turbo`（精度と速度のバランスが良い）。設定で変更可能
  - 処理はバックグラウンドで行い、UI をブロックしない。閉じても再開できる

### R4. LLM のハルシネーション【事実性】
- **リスク**: 発言されていない決定事項や担当者を創作する
- **対策**:
  - プロンプトで推測を明示的に禁止（[06-prompts.md](06-prompts.md)）
  - `temperature=0.1`、JSON Schema による構造化出力
  - **出力後の検証**（`llm/verify.rs`）:
    - 抽出された人名が `participant` / `context_term` / 文字起こし本文に出現するか
    - 決定事項に含まれる数値・日付が文字起こしに出現するか
    - 出現しないものは破棄せず「要確認」フラグを付けて UI に区別表示する
  - 担当者・期限が不明なら空文字（UI では「担当者未定」「期限未定」）

### R5. チャンク処理での情報消失
- **リスク**: 分割要約の統合過程で決定事項やネクストアクションが落ちる
- **対策**: 各チャンクの抽出結果を**その場で DB に永続化**。統合はコードによる重複排除のみで、
  LLM に「消す」判断をさせない

### R6. whisper の無音区間での繰り返し出力
- **リスク**: 無音や雑音で同じ文が延々と出力される
- **対策**: VAD で無音チャンクをスキップ、`no_speech_threshold` を設定、
  同一テキストの連続を後処理で除去

### R7. リアルタイム処理によるリソース競合
- **リスク**: リアルタイム whisper と Ollama が同時に走り、録音が詰まる
- **対策**: 録音経路とリアルタイム経路をチャンネルで分離（`try_send`）。
  会議中は `small` まで。終了後処理は会議中に走らせない

### R8. マイク権限
- **リスク**: 権限が無いと無音を録り続ける
- **対策**: 開始前に権限を確認し、開始後 3 秒間レベルがゼロなら警告を表示

### R9. Ollama 未導入
- **リスク**: AI 機能が全く動かない
- **対策**: 起動時と設定画面で検出し「必要なコンポーネントがありません」を明示 + 導入手順を案内。
  未導入でも録音・文字起こしは完走する

### R10. ディスク容量
- **目安**: WAV 32KB/秒 = 約115MB/時。3時間で約346MB。モデルは 0.5〜3GB
- **対策**: 開始前チェック（想定3時間分 + 余裕）、録音中の定期チェック

## 2. macOS の注意点

| 項目 | 内容 |
|---|---|
| マイク権限 | `Info.plist` に `NSMicrophoneUsageDescription` が必須。無いと**クラッシュ**する。Tauri では `tauri.conf.json` の `bundle.macOS.infoPlist` に記述 |
| TCC | 初回起動時にダイアログ。拒否された場合は「システム設定 > プライバシーとセキュリティ > マイク」への導線を出す |
| Metal | whisper-rs の `metal` feature を有効化。Apple Silicon で大幅に高速化 |
| スリープ抑止 | 録音中は `IOPMAssertionCreateWithName`（`PreventUserIdleSystemSleep`） |
| 音声圧縮 | OS 標準の `afconvert` で m4a 化できる（外部依存不要） |
| 配布 | 署名 + 公証が必要。未署名だと Gatekeeper に阻まれる |
| パス | 保存先の既定は `~/Documents/B-Listener/Meetings` |
| ファイル名 | `:` は Finder 上で `/` として扱われる。会議名から除去する |

## 3. Windows の注意点

| 項目 | 内容 |
|---|---|
| オーディオ | WASAPI。既定デバイスの変更（Bluetooth接続など）を検知する必要がある |
| ビルド | Visual Studio Build Tools（C++）+ CMake が必要 |
| GPU | CUDA / Vulkan は任意。既定は CPU（配布の単純化のため） |
| スリープ抑止 | `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` |
| パス | `\` 区切り。260文字制限に注意し、会議フォルダ名は 60 文字程度に切り詰める |
| ファイル名禁止文字 | `\ / : * ? " < > \|` と予約語（`CON`, `PRN`, `AUX`, `NUL`, `COM1`〜, `LPT1`〜） |
| Defender | 初回のモデルダウンロードがスキャンされ遅くなることがある |
| 音声圧縮 | 標準の変換手段が無い。MVP では WAV のまま保持する |
| WebView2 | Tauri は WebView2 ランタイムを要求する。インストーラで同梱する |

## 4. 共通の注意点

- ファイルは UTF-8（BOM なし）。改行は LF で統一し、Windows 向け出力時のみ必要に応じて CRLF
- 日時は DB に ISO8601（ローカルタイムゾーンのオフセット付き）で保存し、表示時に整形
- 会議フォルダ名が衝突する場合は末尾に `-2`, `-3` を付与
- ログには会議の**本文を出力しない**（個人情報保護）。ID と処理時間のみ
