# 07. ブラウザ版（社内サーバ）

デスクトップ版をインストールせず、**ブラウザから使う**ための構成です。

---

## 1. なぜクラウド（Vercel 等）では動かないのか

このアプリの機能は、その大半がネイティブ処理です。

| 機能 | ブラウザ単体 | クラウド（Vercel 等） |
|---|---|---|
| 録音をディスクへ逐次保存・クラッシュ復旧 | ✕ | △（サーバ側なら可能） |
| whisper.cpp による文字起こし | ✕ | ✕（数百MB〜数GBのモデル、実行時間制限） |
| Ollama によるAI分析 | ✕ | ✕（GPU/常駐プロセスが必要） |
| SQLite・会議フォルダ | ✕ | △ |

さらに決定的な問題として、クラウドに処理を置くと
**会議の音声・文字起こし・利用者名などを社外のサーバへ送ることになります。**
これは本プロジェクトの最優先方針（個人情報を外部へ送信しない・有料APIに依存しない）と
真っ向から衝突します。

そのため本アプリのブラウザ版は、**社内のPC/サーバでサーバプロセスを動かし、
同じ社内ネットワークのブラウザから使う**構成にしています。
データは社内から一歩も出ません。

---

## 2. 構成

```
  ┌─────────────────── 社内ネットワーク ───────────────────┐
  │                                                        │
  │   [ブラウザ]  ──── HTTP ────▶  [B-Listener サーバ]      │
  │    ・マイク取得                  ・WAVへ逐次書き込み      │
  │    ・16kHz PCM を1秒ごと送信      ・whisper.cpp          │
  │    ・SSEで進捗を受信              ・Ollama               │
  │                                   ・SQLite / 会議フォルダ │
  └────────────────────────────────────────────────────────┘
                    ※ インターネットへは出さない
```

デスクトップ版とブラウザ版は**同じコア処理・同じ保存先**を使います
（`state::AppState` を共有し、違いは「UIへの通知の送り先」だけ）。
同じPCで両方を使っても、会議データは 1 か所にまとまります。

### 録音の安全性はデスクトップ版と同じ

ブラウザから届いた PCM は、デスクトップ版とまったく同じ `WavSink` を通して
ディスクへ書かれます。したがって以下の性質が保たれます。

- メモリに溜め込まない（ブラウザ側の保持も最大数秒）
- 5秒ごとに flush + WAVヘッダ更新 + sync
- サーバが落ちても、そこまでの音声はヘッダ修復だけで全復元できる
- **送信に失敗したチャンクは捨てずに再送する**（ブラウザ側のキュー）

## 3. 起動方法

### 準備

```bash
npm install
npm run build          # フロントエンドをビルド（dist を作る）
```

### 起動

```bash
cd src-tauri
cargo run --release --features server --bin b-listener-server
```

起動すると接続先が表示されます。

```
  このPC        : http://localhost:8787
  社内LANから   : http://192.168.0.154:8787
```

### 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `B_LISTENER_HOST` | `0.0.0.0` | 待ち受けアドレス |
| `B_LISTENER_PORT` | `8787` | 待ち受けポート |
| `B_LISTENER_WEB_ROOT` | `dist` を自動探索 | フロントエンドの場所 |

## 4. 重要な制約: 他のPCから録音するには HTTPS が必要

ブラウザは **暗号化されていない接続（`http://`）でのマイク使用を禁止**しています。
例外は `localhost` のみです。

| アクセス方法 | 閲覧・議事録確認 | **録音** |
|---|---|---|
| サーバPC本体から `http://localhost:8787` | ✅ | ✅ |
| 他のPCから `http://192.168.x.x:8787` | ✅ | ❌ ブラウザが拒否 |
| 他のPCから `https://...` | ✅ | ✅ |

アプリはこの状況を検出し、会議中の画面に対処方法を表示します。

**現時点では HTTPS 対応は未実装です。** 他のPCから録音する運用が必要な場合は、
次のいずれかで対応します（未実装・要判断）。

1. サーバに自己署名証明書を持たせ、各PCのブラウザに一度だけ信頼させる
2. 社内のリバースプロキシ（nginx 等）で HTTPS を終端する
3. 社内認証局の証明書を使う

閲覧・議事録の確認・AI処理の実行だけであれば、平文の LAN アクセスでも問題ありません。

## 5. API

デスクトップ版の Tauri コマンドと**同じコマンド名・同じ引数**を使います。
そのためフロントエンドは 1 箇所（`src/lib/ipc.ts`）だけで両対応しています。

| エンドポイント | 用途 |
|---|---|
| `POST /api/command/<name>` | コマンド実行（Tauri の `invoke` と等価） |
| `GET /api/events` | 進捗通知（SSE。Tauri のイベントと等価） |
| `POST /api/recording/chunk?meetingId=...` | 16bit PCM チャンクの送信 |
| `GET /api/audio/<meetingId>` | 録音音声の再生 |
| `GET /api/download/<meetingId>/<audio\|transcript\|minutes\|summary>` | 成果物のダウンロード |
| `GET /api/health` | 稼働確認 |

エラーはデスクトップ版と同じ `{ "code": "...", "message": "..." }` で返ります。

## 6. ブラウザ版で使えない機能

| 機能 | 理由 |
|---|---|
| 保存先フォルダの選択・「フォルダを開く」 | ブラウザから利用者のPCのフォルダを操作できない |
| マイクの選択 | ブラウザ側の設定で選ぶ |
| 保存先の指定ダイアログ | ダウンロードで代替 |

保存先フォルダは**サーバPCのパス**として表示・編集できます。

---

## 7. 運用上の注意

- **インターネットへ直接公開しないこと。** 認証機能を持たないため、
  アクセスできる人は全会議を閲覧できます。社内LANに限定してください。
- 同時に録音できるのは 1 会議までです（デスクトップ版と共通）。
- サーバPCはスリープさせないでください（録音中は自動で抑止しますが、
  常時運用する場合は電源設定の見直しを推奨します）。
